# entityfy-core

Model definition, SQL generation, query DSL, backends, and statement cache.

Reads stream: `backend::query_each` hands one reused row buffer to the caller, so `find`,
`find_one`, `find_many` and `exists` materialize straight into the model instead of building a
`vector<vector<sql_value>>` first. `exists` stops at the first row.

Writes: `table.update(entity)` writes every column, because the core keeps no snapshot.
`table.update_partial(entity, &T::name, ...)` writes exactly the columns the caller names - the
statement carries only those binds and no `updated_at` guesswork:

```cpp
auto& stored = ...;
stored.name = "Ada Lovelace";
db.update_partial(stored, &user::name);   // the rest of the row is left as it is
```

## Model definition

An entity is a plain C++ struct; which column it maps to in the table is specified with an
annotation.

```cpp
struct [[= entityfy::table{"users"}]] user
{
    [[= entityfy::id, = entityfy::auto_increment]]
    std::int64_t id = 0;

    [[= entityfy::unique, = entityfy::indexed, = entityfy::not_null, = entityfy::varchar{320}]]
    std::string email;

    [[= entityfy::not_null, = entityfy::varchar{120}]]
    std::string name;

    [[= entityfy::created_at, = entityfy::timestamp]]
    std::chrono::system_clock::time_point created_at{};

    [[= entityfy::ignore]]
    std::vector<std::string> tags;   // not persisted
};
```

### Annotations

| Annotation | Meaning |
|---|---|
| `entityfy::id` / `entityfy::primary_key` | Primary key |
| `entityfy::auto_increment` | Generated by the database (SQLite `AUTOINCREMENT`, PG `GENERATED ... IDENTITY`) |
| `entityfy::unique`, `entityfy::indexed` / `index` | Unique / indexed column |
| `entityfy::not_null`, `entityfy::nullable` | Nullability |
| `entityfy::varchar{n}`, `entityfy::text`, `entityfy::blob`, `entityfy::json`, `entityfy::uuid`, `entityfy::decimal{p,s}` | Column type |
| `entityfy::date`, `entityfy::time`, `entityfy::timestamp` | Time types |
| `entityfy::created_at`, `entityfy::updated_at` | Automatic timestamp |
| `entityfy::references{"table", "column", "ON DELETE", "ON UPDATE"}` | Foreign key |
| `entityfy::column{"sql_name"}` | Explicit SQL column name (default: the member name); used by DDL and by every statement the core and context layers build |
| `entityfy::ignore` / `entityfy::ignored` | Not a column, a transient field |

Supported field types: `bool`, integral, floating point, enum, `std::string`,
`std::vector<std::byte>`, `std::optional<T>`, chrono types (`sys_days`,
`system_clock::time_point`, durations).

## Connection and schema

```cpp
entityfy::client db{"sqlite://app.db"};          // SQLite
entityfy::client db{"postgres://host=... dbname=app"};  // PostgreSQL

db.migrate<user>();          // creates the table + indexes (idempotent)
db.migrate_force<user>();    // forces past a schema validation error
db.reset_schema<user>();     // drops and recreates the table
db.validate_schema<user>();  // drift report
db.inspect_table("users");   // live schema information
```

## CRUD and queries

```cpp
db.insert(user{.email = "a@b.c", .name = "Ada"});
db.insert_many(users);                 // a SINGLE statement for a model with explicit keys
db.update(user{.id = 1, ...});         // by PK
db.update_many(patch, filter);         // UPDATE ... WHERE
db.find_one(entityfy::where(&user::email).eq("a@b.c"));
db.find_many(entityfy::where(&user::name).starts_with("A").order_by(&user::id).take(10));
db.count(entityfy::where(&user::id) > 0);
db.exists(entityfy::where(&user::email).eq("a@b.c"));
db.remove_by_id(1);
db.delete_many(entityfy::where(&user::id) < 100);
```

### Multi-row INSERT

For models with explicit keys, `insert_many` produces a **single**
`INSERT ... VALUES (?,?),(?,?)...` statement; batches are split according to the
`set_batch_parameter_limit` value. For models with auto-increment keys, generated ids are fetched
row by row, so that path runs row by row.

```cpp
db.set_batch_parameter_limit(500);      // at most 500 parameters per statement
const auto result = db.insert_many(items);
```

Measured effect (SQLite, 20.000 rows): row by row 674k rows/s → `insert_many` 2,79M rows/s
(**4,1x**). Details: [benchmarks.md](benchmarks.md).

### SQL logger

```cpp
db.set_logger([](std::string_view sql) { std::cout << sql << '\n'; });
```

Every executed statement is handed to the logger before it runs.

### Value converter (custom types)

To write/read your own type to/from a single column, specialize `entityfy::value_converter<T>`:

```cpp
struct geo_point
{
    double latitude = 0.0;
    double longitude = 0.0;
};

template <>
struct entityfy::value_converter<geo_point>
{
    static geo_point to_value(const entityfy::sql_value& raw)
    {
        // "41.01,28.97" -> geo_point
    }

    static entityfy::sql_value from_value(const geo_point& value)
    {
        return std::format("{:.2f},{:.2f}", value.latitude, value.longitude);
    }
};

struct [[= entityfy::table{"places"}]] place
{
    [[= entityfy::primary_key]]
    std::int64_t id = 0;

    geo_point position;   // written to a single TEXT column
};
```

This field goes to an untyped (`TEXT` by default) column. Annotations you can use to control
this:

| Annotation | Result |
|---|---|
| — (default) | `TEXT` column |
| `[[= entityfy::text]]` | `TEXT` column |
| `[[= entityfy::varchar{n}]]` | `VARCHAR(n)` column |
| `[[= entityfy::json]]` | `JSONB` on PostgreSQL, `TEXT` on SQLite — the converter **must** produce **valid JSON** |
| `[[= entityfy::sql_type{"..."}]]` | Raw SQL type (e.g. `"VARCHAR(64)"`) |

The `uuid`, `date`, `time`, and `timestamp` annotations are valid only on `std::string` (or a
suitable chrono) fields; use the ones above for converter types.

It can also be used for `std::optional<T>` and JSON columns — so composite/JSON types can be
stored without changing the database schema.

Filter language: `eq`, `ne`, `lt`, `le`, `gt`, `ge`, `in`, `in_range`, `between`, `is_null`,
`is_not_null`, `like`, `starts_with`, `ends_with`, `contains`.

Aggregates: `sum`, `avg`, `min`, `max`, `count`, and their grouped variants
`count_by`, `sum_by`, `avg_by`, `min_by`, `max_by`.

Raw SQL:

```cpp
const auto rows = db.query(entityfy::statement{
    .sql = "SELECT \"id\" FROM \"users\" WHERE \"name\" = ?",
    .binds = {std::string("Ada")}});
```

## Transaction

```cpp
db.transaction([&] {
    db.insert(user{.email = "a@b.c", .name = "Ada"});
    db.insert(user{.email = "d@e.f", .name = "Grace"});
});
```

Nested transactions use savepoints (`entityfy_tx_<n>`).

## Migration history

The versioned migration history is kept in the `entityfy_schema_migrations` table
(`entityfy::migration_history_table`). Records are read only from this table; if the history
table name changed, it must be moved with the upgrade command in the
[migration guide](migration.md).

## Statement cache

```cpp
db.set_statement_cache_capacity(64);  // default 32, 0 = disabled
db.statement_cache_size();             // how many statements are cached
db.clear_statement_cache();
```

Only the SQLite backend reuses statements; the PostgreSQL backend reports capacity 0. Details
and measurements: [benchmarks.md](benchmarks.md).

## Errors

Under the `entityfy::orm_error` root: `connection_error`, `sql_error`, `query_error`,
`transaction_error`, `migration_error`, `constraint_error`, and under the latter
`unique_violation`, `foreign_key_violation`, `not_null_violation`.
